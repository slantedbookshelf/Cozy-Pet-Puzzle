# 萌宠投喂屋 · Cozy Pet Puzzle

参考 2048 方向滑动的多角色同步解谜小游戏。Vite + TypeScript + Three.js；纯二维网格逻辑；无后端、数据库或登录。不是经营或点击投喂游戏。

## 启动与验证

Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev
npm test
npm run build
```

打开 `npm run dev` 输出的地址（通常为 http://127.0.0.1:5173/）。`npm run preview` 可预览生产构建，`npm run test:watch` 可监听测试。

## 操作与规则

- 方向键 / WASD / 页面方向按钮：全部动物沿棋盘网格一起滑到底。
- 边界、花箱和其他动物会阻挡；不会穿越、重叠、合并或随机生成动物。
- 已站在目标格的动物依然参与后续移动；不会单独锁定或进食。
- 仅当所有动物同时停在各自目标格时，锁定输入、统一进食并显示通关界面。
- 滑动与进食动画期间，方向、撤销和重置输入禁用；长按键盘不会排队连走。
- 无效滑动不计步、不产生撤销记录。撤销恢复完整动物状态和步数。
- 拖动/滚轮仅调整镜头，不改变棋盘方向；右上按钮恢复视角。
- 彩色地垫为目标站位，食品柜台位于活动区域之外。

## 三关配置与正确路径

坐标从 0 开始，`x` 向右、`y` 向下。`y = -1` 为上边界外的食物位置。路径均由 BFS 验证，且为最短路径；每一步要等动画结束后再输入。

| 关卡 | 棋盘 | 初始位置 | 目标位置 | 固定障碍 | 解法 |
| --- | --- | --- | --- | --- | --- |
| 1 第一口小鱼干 | 4 × 4 | 猫 (0,3) | 猫 (3,0) | 无 | ↑ →（2 步） |
| 2 刚刚好的停靠 | 5 × 5 | 猫 (0,4) | 猫 (2,0) | (0,1)、(3,2) | ↑ → ↑（3 步） |
| 3 一起开饭吧 | 5 × 5 | 猫 (0,4)、狗 (4,4) | 猫 (4,0)、狗 (3,0) | (0,1)、(3,2)、(1,3) | → ↑ ← ↑ →（5 步） |

食物位置为各目标的 `(x,-1)`：猫对应小鱼干，狗对应狗粮。兔子/胡萝卜的类型与渲染已支持，但按第一阶段关卡要求不加入这三关。

第三关逐步状态：

| 输入 | 猫 | 狗 |
| --- | --- | --- |
| 初始 | (0,4) | (4,4) |
| → | (3,4) | (4,4) |
| ↑ | (3,3) | (4,0) |
| ← | (2,3) | (0,0) |
| ↑ | (2,0) | (0,0) |
| → | (4,0) | (3,0) |

最后一步猫先确定最右侧位置，狗被猫挡住，停在相邻目标。两者同时满足才通关。

## 架构

`src/game/` 完全不依赖 Three.js、DOM 或帧时间：

- `types.ts`：二维坐标、动物、目标、关卡和移动计划。
- `Board.ts`：边界、障碍及配置合法性检查。
- `MovementEngine.ts`：纯函数；按运动方向从前到后确定最终位置，返回完整起终点计划，不修改输入。
- `WinChecker.ts`：仅检查当前状态是否全员对应目标。
- `Game.ts`：ready → moving → eating → won 状态机、撤销、重置、步数和关卡切换。
- `LevelManager.ts` / `levels.ts`：三个固定关卡与保存的解法。
- `solver.ts`：BFS 搜索，测试时独立验证可解性与最短解法。

`src/render/` 负责 Three.js 展示：

- `SceneManager.ts`：场景生命周期、画面缩放、灯光、资源释放；通过 GameView 接口连接逻辑层。
- `boardScene.ts`：自然木地板、目标地垫、外部食物柜台、障碍花箱和室内装饰。
- `AnimalRenderer.ts`：共享插值进度的同步滑动、统一进食动画；动画不决定逻辑结果。
- `src/characters/pet.ts`：猫、狗、兔子的程序化卡通造型和待机动画。
- `src/core/InputManager.ts`：键盘和方向按钮输入，不提供单角色移动功能。
- `src/core/resources.ts`：glTF 加载接口及几何体、材质、纹理、阴影贴图清理。
- `src/ui.ts` / `src/style.css`：响应式界面、可聚焦控件和通关对话框。

统一插值的动物间距是起终点间距的凸组合，因此同一行/列中移动时也不会互相穿越。目标逻辑不依赖动画 FPS。页面隐藏时暂停动画，支持减少动态效果设置，像素比上限为 2。换关/HMR/退出时释放场景资源。

## 验证范围

Vitest 覆盖四方向边界、固定障碍、前后顺序、不同距离、不能越过/重叠/合并、无效移动、外部食物不可进入、部分到位后继续移动、同时胜利、动画输入锁、撤销/重置和 BFS 解法。

额外穷举 3×3 障碍棋盘上三只动物的所有合法排列与四个方向（1,344 个场景），与独立的逐格同步模拟器比较结果。

浏览器实际走通三关并检查撤销；静态构建同时运行 TypeScript 检查。Three.js 打包体积可能产生 Vite 的 500 KB 提示，不影响构建；目前未引入后处理或外部纹理。

## 美术资源

当前动物与场景均为程序化模型，没有第三方 GLB/glTF 文件，也未声称下载模型。保留 glTF 加载接口和 `public/models/README.md`，以后引入资产须记录来源、许可和署名。本阶段没有加入经营、金币、商店、存档或后续关卡系统。

## 全屏街区与角色动画升级

画布铺满浏览器视口，浮层只保留 Level、步数、撤销、重置、视角复位和方向按钮。首次操作提示使用 sessionStorage，每次会话只显示一次。中心店铺采用自然木地板和圆形目标地垫；网格坐标与逻辑花箱仍保持原样。

环境按空间分区，新增/升级模块：

- `src/render/environment/Diorama.ts`：装配核心店铺、相邻房间、街道和外围街区。
- `src/render/environment/neighbourhood.ts`：连接道路、路口、咖啡馆、便利店、住宅、花园和远处建筑。大型树木全部布置在室外。
- `src/render/environment/rooms.ts`、`street.ts`、`props.ts`：洗护间、休息室、花店立面、家具、玩具、包裹、自行车、车辆及室外绿化。
- `src/render/environment/surfaces.ts`、`batch.ts`：连续木地板、脚印、接触阴影、按 6 单位空间分块的静态合批。屏幕外街区保留视锥裁剪；远处建筑不投射实时阴影。
- `src/render/boardScene.ts`、`SceneManager.ts`、`src/core/camera.ts`、`src/world/lighting.ts`：核心场景、生命周期、全屏响应式取景与暖色光照。
- `src/ui.ts`、`src/style.css`：极简半透明界面。
- `src/characters/pet.ts`：四肢、耳朵、眼睛及下颌的独立运动节点。
- `src/render/AnimalRenderer.ts`：起跑蓄力、共享五次平滑曲线、短弧转向、奔跑、减速停稳、期待、统一进食、开心反馈。
- `src/render/AnimalRenderer.test.ts`、`src/render/environment/environment.test.ts`：新增动画时序、24/60/144 FPS 终点与间距、局部关节及场景净空检查。

猫采用高频小步幅；狗使用更大的肢体摆幅和弹性；兔子使用双腿成组跳跃与耳朵滞后。位置变化始终采用同一插值进度，动画结束强制对齐逻辑终点。单只到位仅朝向食物并嗅闻，嘴部不咀嚼；全部同时到位才依次转向、进食、开心，2.65 秒后结束庆祝 Promise，游戏控制器随后显示通关弹窗。减少动态效果偏好会缩短移动并关闭奔跑起伏、耳朵摇动和树叶摆动。

所有 `src/game/` 文件保留原始内容，可对照 `logic-baseline.json` 的 SHA256。三关配置、BFS 解法、胜利与撤销规则均未修改。兔子动画已实现并单测，但原有三个教学关卡只使用猫与狗，因此没有擅自增加兔子关卡。

视觉局限：仍为程序化组合模型，没有蒙皮骨骼、IK 脚部贴地、嘴与食物精确接触、食物真实消耗或布料模拟。接触阴影是柔和贴片与方向光阴影组合，没有屏幕空间 AO。外围建筑使用统一的模块化立面，远景细节有限；低端设备实际帧率还需真机测试。
